# 在使用者電腦上怎麼跑研究（網頁介面）

環境見 `P6_ENV.md`。研究都在網頁介面操作：「研究 → 一鍵研究」。介面有三種模式，頁面最上面可以切換。

## 一次性準備（`F:\treepolo-p6`）
```
git pull origin claude/hello-rc9nc6
D:\soft\Python313\python.exe -m pip install --no-cache-dir F:\treepolo-p6 --upgrade
```
（安裝前先關掉網頁服務，否則檔案被鎖。不要用 `-e`。）

## 啟動
雙擊 `F:\treepolo-p6\啟動介面.bat`（黑色視窗不要關，關掉就是停止服務；研究執行中更不要關），或在 `F:\treepolo-p6` 執行 `D:\soft\Python313\Scripts\treepolo-mlb.exe ui`。左邊選單「研究 → 一鍵研究 Run Everything」。

## 簡單模式
選運算量（快速約 1 小時；標準約 3 小時；冒煙只確認跑得通）與手別組，按「開始」。依序做五步：模型參數搜尋 → 訓練模型 → 固定效應對照答案 → 決策引擎與情境表 → 查詢工具與驗收。每個步驟顯示進度、已用時間，和依進度推算的剩餘時間（粗估）。簡單模式用梯度提升樹、不開任何偏差控制。

完成後頁面下方是結果摘要，全部是數字、區間和樣本數，**沒有「通過／不通過」或「偵測到」的判定**：
- 用的模型與偏差控制；
- 引擎對照：引擎照實際配球算出的期望失分，和真實資料統計出的得分期望值表差多少（0＝完全一致）；
- 每種政策每打席少失幾分（區間、每隊每季）；
- 球員描述或效應的預測增益（對「全部控制都關掉」的同一個模型；沒見過的球員、沒訓練過的年份）；
- 各球種相對一般配球的差異；
- 比較了幾個、純靠運氣預期有幾個「看起來有效」、實際有幾個；
- 換年份重看：每個年份單獨訓練一份模型，並排放在研究紀錄裡。

中途失敗：頁面會寫是哪一步、為什麼；已完成的步驟會保留，修好後再按「開始」會從失敗的那一步繼續（相同設定的結果會沿用）。

## 完整設定模式
按「完整設定模式」，頁面把**目前簡單模式會跑的設定整份寫出來**，每個步驟一個分頁（參數搜尋、訓練模型、固定效應對照、決策引擎、查詢）。每個設定都有欄位、預設值、中英說明；選項用下拉選單，列表用逗號分開，JSON 設定有即時檢查。可以改：
- **模型**：邏輯迴歸、梯度提升樹、混合效應、神經網路＋球員嵌入、序列模型（後兩種需要 PyTorch，已裝在 `D:\soft\Python313`）。
- **偏差控制**（讓模型不要學歪，作用在被訓練、被拿來算期望失分的模型本身）：
  - 投手整體好壞、打者整體好壞（不控制／用描述特徵／每人一個效應／只在同一人之內比較）；
  - **投手×球種**：每位投手的每一種球各一個效應（擋「敢連投的人本來那顆球就強」）、打者×球種；
  - 投手當天狀態（每位投手每場一個效應）、當天×球種；
  - 存活偏誤（球數＋打者）、球的位置。
  - 每個效應都有自己的收縮強度（假想樣本數，愈大愈往聯盟平均收縮）。
- 年份：任何年份組合都可以，介面不再有保留球季的限制。
- 「略過」：參數搜尋與固定效應對照可以取消勾選。

按鈕：**驗證**（逐步驟逐欄位檢查，有問題的欄位會標紅）、**匯出設定檔**、**匯入設定檔**、**開始**（驗證通過才會開始）。

### 設定檔
JSON（UTF-8，不帶 BOM），格式：
```json
{"format": 1, "created_at": "...", "groups": ["RvR"], "years": [2023, 2024],
 "steps": {"search": {...}, "train": {...}, "anchor": {...}, "policy": {...}, "query": {...}},
 "enabled": {"search": true, "anchor": true}}
```
`groups` 與 `years` 在最上面，全部步驟共用；各步驟後面的編號（`model_run_id` 等）不用寫，執行時會自動接上前面步驟的結果。匯入有錯的檔案時，介面仍會載入，並把有問題的欄位標紅。

## 比較模式
勾選多種模型（可各自改設定，共用的設定寫在下面），先按**預估時間**：每種模型會先在約 2% 的資料上實際試跑一小段，再依成本規則推算全量要多久（樹：列數×棵數×成員數；神經網路：列數×輪數；邏輯迴歸：列數），顯示每種模型的預估與合計，寫明「粗估，實際可能是 0.5 到 2 倍」，以及試跑本身花的時間。看過預估再按**開始比較**。

同一份資料、同一組切分、同一個種子訓練每一種，並排列出：留出年份與沒見過的球員上的對數損失、Brier、各類結果的損失、校準誤差、訓練時間；每種模型的球種效果（同一批列）和每兩種模型之間的差；每種模型用了哪些偏差控制。**沒有「哪個最好」的判斷**，只能選排序欄位。完整的表在「研究紀錄」裡。

## 注意
- 不要同時開多個重運算工作；記憶體 16 GB。長工作不因超過估計時間而中止。
- 顯卡只有 4 GB 顯存，桌面程式平時佔約 3 GB：神經網路的批次預設較小，顯存不足時會自動減半並在擬合摘要說明。
- 序列模型要用到打席內的投球順序，所以可以訓練與比較，但**不能**當決策引擎用的模型。
- 沒有網頁介面時的備用做法：`docs/research/scripts/run_configs.py` 搭配 `docs/research/configs/p6/` 的設定檔（舊方式，只有舊的研究方法）。

## 情境查詢
網頁「研究 → 情境查詢」；或命令列：
```
D:\soft\Python313\Scripts\treepolo-mlb.exe research query <查詢紀錄編號> --group RvR --balls 1 --strikes 2 --outs 1 --bases 100 --prev SL --streak 2
D:\soft\Python313\Scripts\treepolo-mlb.exe research query <查詢紀錄編號> --group RvR --find pitcher:Skenes
```
指定投手或打者時，用的是同一個訓練好的模型（球員自己的效應）；模型沒見過的球員，答案等於聯盟平均，回應裡會寫出來。每個答案列出每種球的數字、區間、區間重疊的群組、比較了幾種球與純靠運氣的預期，以及模型用了哪些偏差控制。
